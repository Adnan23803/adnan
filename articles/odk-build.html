ODK Build : concevoir des formulaires XLSForm sans coder ODK Build: design XLSForm forms without coding

Une application gratuite, utilisable hors connexion, qui permet à n'importe quel professionnel du terrain de construire ses formulaires de collecte — des questions simples aux coordonnées GPS — et de générer un fichier XLSForm en quelques clics. A free, offline-capable application that lets any field professional build data collection forms — from simple questions to GPS coordinates — and generate an XLSForm file in just a few clicks.

Adnan Adamou Data Analyst & Information Manager · Niamey, Niger Data Analyst & Information Manager · Niamey, Niger

Concevoir un formulaire XLSForm rigoureux est souvent le premier obstacle que rencontrent les équipes de terrain. ODK Build lève cette barrière en proposant une interface graphique intuitive, utilisable sans connexion internet et sans toucher à une seule formule Excel.

Qu'est-ce qu'ODK Build ?

ODK Build est un outil gratuit développé par la communauté Open Data Kit (ODK), désormais maintenu par l'organisation Getodk.org. Il s'agit d'un éditeur visuel de formulaires de collecte de données qui génère en sortie un fichier au standard XLSForm — le format universel lu par KoboToolbox, ODK Collect, CommCare et la plupart des plateformes de collecte mobile.

Son avantage principal : vous construisez votre formulaire par glisser-déposer, sans écrire une seule ligne de code ni maîtriser la syntaxe XLSForm. L'application s'occupe de générer le fichier .xlsx ou .xml pour vous.

ODK Build en ligne vs. version desktop

ODK Build existe sous deux formes :

  • Version en ligne sur build.getodk.org — accessible depuis un navigateur, nécessite une connexion internet.
  • Version desktop (Windows 32/64 bits et Mac OS) — s'installe sur votre machine et fonctionne entièrement hors connexion. C'est celle que je recommande pour le terrain.

Découverte de l'interface

Au premier lancement, ODK Build vous présente une interface épurée divisée en trois zones principales :

  1. La barre de types de questions (en haut) — elle liste tous les types de champs disponibles : texte, nombre, date, image, audio, GPS, liste à choix unique, liste à choix multiple, etc.
  2. La zone de construction (au centre) — c'est ici que vous glissez et organisez vos questions.
  3. Le panneau de propriétés (à droite) — il affiche les paramètres de la question sélectionnée : libellé, contrainte, condition d'affichage, etc.

La navigation est volontairement simple. Vous n'avez pas besoin de formation technique pour commencer à l'utiliser.

Types de questions disponibles

ODK Build couvre l'essentiel des besoins d'une enquête terrain :

  • Text — question ouverte, réponse libre
  • Number — champ numérique (entier ou décimal)
  • Select One — liste à choix unique (radio)
  • Select Multiple — liste à choix multiples (cases à cocher)
  • Date / Time / Date and Time — saisie de dates et heures
  • GPS Location — capture des coordonnées géographiques (latitude, longitude, altitude, précision)
  • Image / Audio / Video — capture de médias depuis l'appareil
  • Barcode — lecture de code-barres ou QR code
  • Note — texte informatif affiché à l'enquêteur sans saisie
  • Group — regroupement de questions en sections
  • Repeat — répétition d'un groupe de questions (utile pour les membres d'un ménage par exemple)
Pour la majorité des enquêtes humanitaires et sociales, ces types couvrent 95 % des besoins. Les cas avancés (listes en cascade, calculs complexes, géofencing) nécessiteront d'éditer directement le XLSForm généré.

Construire un formulaire pas à pas

Voici comment créer un formulaire simple d'identification d'un ménage :

1. Créer un nouveau formulaire

Au lancement, ODK Build crée automatiquement un formulaire vide. Vous pouvez aussi aller dans File → New Form. Donnez un titre à votre formulaire en haut de l'interface.

2. Ajouter des questions

Cliquez sur le type de question souhaité dans la barre du haut — un nouveau champ apparaît dans la zone centrale. Renseignez ensuite dans le panneau de droite :

  • Label : le libellé de la question affiché à l'enquêteur
  • Name : l'identifiant technique (sans espace, sans accent, ex. nom_chef_menage)
  • Hint : une indication optionnelle affichée sous la question
  • Required : cochez si la question est obligatoire

3. Configurer une liste à choix

Pour un Select One ou Select Multiple, cliquez sur Edit Choices dans le panneau de droite. Une fenêtre s'ouvre pour saisir les options une par une (libellé + valeur technique).

4. Ajouter une question GPS

Glissez le type GPS Location dans votre formulaire. Lors de la collecte sur ODK Collect, l'application demande automatiquement à l'enquêteur d'activer le GPS et capture les coordonnées. Aucune configuration supplémentaire n'est nécessaire dans ODK Build.

5. Organiser en groupes

Pour structurer votre formulaire en sections (ex. "Identification", "Logement", "Nutrition"), glissez un bloc Group et faites glisser vos questions à l'intérieur. Cela améliore la lisibilité et, dans KoboToolbox, génère automatiquement un affichage en pages séparées.

Exporter le formulaire

Une fois votre formulaire construit, exportez-le en allant dans File → Export to XLSForm. ODK Build génère un fichier .xlsx que vous pouvez :

  • Importer directement dans KoboToolbox (Nouveau projet → Importer un XLSForm)
  • Importer dans ODK Central ou ODK Aggregate
  • Ouvrir dans Excel pour des modifications avancées (listes en cascade, calculs, etc.)

Vous pouvez aussi sauvegarder votre formulaire au format natif ODK Build (.odkbuild) pour le reprendre plus tard.

Limites à connaître

ODK Build est excellent pour démarrer, mais il a des limites dont il faut être conscient :

  • Pas de listes en cascade — si vous avez besoin de listes filtrées (Région → Département → Commune), vous devrez éditer le XLSForm dans Excel.
  • Pas de calculs automatiques — les champs calculés (âge à partir d'une date de naissance, score composite, etc.) nécessitent la syntaxe XLSForm directement.
  • Pas de logique de saut complexe — les conditions d'affichage simples sont gérées, mais les expressions complexes devront être éditées manuellement.
  • Interface en anglais uniquement — les libellés de l'interface ne sont pas traduits, même si les questions de votre formulaire peuvent être en n'importe quelle langue.

Pour ces cas avancés, je recommande de commencer dans ODK Build puis de finaliser le XLSForm dans Excel. C'est la meilleure approche pour les équipes mixtes (techniciens et non-techniciens).

Conclusion

ODK Build est la porte d'entrée idéale pour toute équipe qui souhaite se lancer dans la collecte mobile de données sans passer par la case technique. En quelques heures de prise en main, vous pouvez construire des formulaires professionnels, les exporter au format XLSForm et les déployer sur KoboToolbox ou ODK Collect.

Pour les formulaires plus complexes, ODK Build reste utile pour la structure de base — vous compléterez ensuite les fonctionnalités avancées directement dans le fichier Excel. C'est une combinaison qui fonctionne très bien en contexte humanitaire et de développement, où les équipes ont des profils techniques variés.

Designing a rigorous XLSForm is often the first obstacle field teams encounter. ODK Build removes this barrier by offering an intuitive graphical interface, usable without internet connection and without touching a single Excel formula.

What is ODK Build?

ODK Build is a free tool developed by the Open Data Kit (ODK) community, now maintained by Getodk.org. It is a visual editor for data collection forms that outputs a file in the XLSForm standard — the universal format read by KoboToolbox, ODK Collect, CommCare and most mobile data collection platforms.

Its main advantage: you build your form by drag and drop, without writing a single line of code or mastering XLSForm syntax. The application handles generating the .xlsx or .xml file for you.

ODK Build online vs. desktop version

ODK Build comes in two forms:

  • Online version at build.getodk.org — accessible from a browser, requires an internet connection.
  • Desktop version (Windows 32/64-bit and Mac OS) — installs on your machine and works entirely offline. This is the one I recommend for field use.

Discovering the interface

On first launch, ODK Build presents a clean interface divided into three main areas:

  1. The question type bar (top) — lists all available field types: text, number, date, image, audio, GPS, single-select, multi-select, etc.
  2. The build area (center) — drag and arrange your questions here.
  3. The properties panel (right) — shows the parameters of the selected question: label, constraint, display condition, etc.

The interface is intentionally simple. No technical training is needed to start using it.

Available question types

  • Text — open question, free response
  • Number — numeric field (integer or decimal)
  • Select One — single-select list (radio)
  • Select Multiple — multi-select list (checkboxes)
  • Date / Time / Date and Time
  • GPS Location — captures geographic coordinates (lat, lon, altitude, accuracy)
  • Image / Audio / Video — captures media from the device
  • Barcode — barcode or QR code reader
  • Note — informational text displayed without input
  • Group — groups questions into sections
  • Repeat — repeating group (useful for household members)
For the vast majority of humanitarian and social surveys, these types cover 95% of needs. Advanced cases (cascading lists, complex calculations, geofencing) will require editing the generated XLSForm directly.

Building a form step by step

Click a question type in the top bar — a new field appears in the central area. In the right panel, fill in:

  • Label: the question text displayed to the enumerator
  • Name: the technical identifier (no spaces, no accents, e.g. hh_head_name)
  • Hint: an optional note shown under the question
  • Required: check if the question is mandatory

For Select One / Select Multiple, click Edit Choices in the right panel to enter options one by one. To organize your form into sections, drag a Group block and nest your questions inside it.

Exporting the form

Once your form is built, export it via File → Export to XLSForm. ODK Build generates an .xlsx file you can:

  • Import directly into KoboToolbox (New project → Import XLSForm)
  • Import into ODK Central or ODK Aggregate
  • Open in Excel for advanced modifications (cascading lists, calculations, etc.)

Known limitations

  • No cascading lists — filtered lists (Region → District → Village) require editing the XLSForm in Excel.
  • No calculated fields — composite scores and date-based calculations need XLSForm syntax directly.
  • No complex skip logic — simple display conditions are handled, but complex expressions must be edited manually.
  • English interface only — form questions can be in any language, but the UI itself is English.

For advanced cases, I recommend starting in ODK Build then completing the XLSForm in Excel. This combination works very well in humanitarian and development contexts where teams have mixed technical profiles.
